# Личные границы (BOUND) — уже реализованная программа

Эта программа **уже есть в продукте** — структура в
[../../../content/modules/bound.yaml](../../../content/modules/bound.yaml).
Материалы сюда кладутся для **доработки**: новая озвучка, правки текста,
уточнения к существующим неделям.

## Весь текущий контент — в читаемых md-файлах рядом

- [OVERVIEW.md](OVERVIEW.md) — паспорт программы (вступление, для кого, что
  получает пользователь), 5+5 маркеров состояния, финальный продукт,
  постмодульная маршрутизация.
- [week-1.md](week-1.md) … [week-6.md](week-6.md) — по одному файлу на неделю:
  вводный экран, все 7 дней (фокус, задание, квиз, рефлексия), 10 вопросов
  недельной самопроверки, зоны GREEN/YELLOW/RED, критичные ответы.

Эти файлы сгенерированы из текущего `content/modules/bound.yaml` — это снимок
того, что прямо сейчас загружено в продукт, не черновик с нуля. Правьте их
свободно: это и есть рабочая копия. Когда правки готовы к переносу в продукт —
скажите, разработчик соберёт их обратно в YAML и перезагрузит.

## Имя файла сценария

**Обязано совпадать с кодом аудио**, чтобы потом не путаться, какой текст к
какой записи:

```
BOUND-W1-A1.md       → AUDIO_BOUND_W1_A1.mp3
BOUND-W1-FINAL.md    → AUDIO_BOUND_W1_FINAL.mp3
```

Слоты: A1 — дни 1–2, A2 — дни 3–4, A3 — дни 5–6, FINAL — день 7.

## Шапка сценария

```markdown
# BOUND-W1-A1

- Код: AUDIO_BOUND_W1_A1
- Хронометраж: ~6 минут
- Статус: черновик | утверждён | записан

[пауза 3 сек] — пауза в начитке, диктору
[мягче] — интонационная пометка, диктору

---

<текст>
```

После записи обновите `duration_sec` и `size_bytes` в `audio_map` в
`content/modules/bound.yaml` — сейчас там значения заглушки у всех 24 записей.
