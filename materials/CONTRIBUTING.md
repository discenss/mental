# Как присылать материалы

Эта инструкция — для автора текстов: методолога, копирайтера, редактора.
Технических знаний не требуется. Выберите один из двух способов.

---

## Способ 1 — через сайт GitHub (рекомендуем)

Ничего устанавливать не нужно, всё делается в браузере.

### Один раз в начале

1. Заведите аккаунт на [github.com](https://github.com), если его нет.
2. Пришлите свой **логин** владельцу проекта — он выдаст доступ.
3. Примите приглашение: придёт письмо, либо откройте
   [github.com/discenss/mental/invitations](https://github.com/discenss/mental/invitations).

### Чтобы добавить файл

1. Откройте [github.com/discenss/mental/tree/main/materials](https://github.com/discenss/mental/tree/main/materials).
2. Зайдите в нужную папку — какую именно, подскажет таблица ниже.
3. Нажмите **Add file → Create new file** (создать) или кликните существующий
   файл и значок карандаша (исправить).
4. Впишите имя файла и текст.
5. Внизу страницы в поле **Commit changes** одной строкой напишите, что сделали
   («сценарий REAL-W1-A1», «правки в описании для App Store»).
6. Нажмите **Commit changes**.

Готово. Файл сохранён, история правок ведётся автоматически — ничего не
потеряется, и всегда видно, что когда менялось.

### Куда какой файл

| Что вы написали | Папка |
|---|---|
| Методический текст, стандарт, исходник программы | `materials/methodology/` |
| Сценарий аудио-практики для программы «Найти себя» | `materials/audio-scripts/real/` |
| Сценарий аудио-практики для программы «Личные границы» | `materials/audio-scripts/bound/` |
| Описание для App Store, лендинг, тэглайны, юр. документы | `materials/marketing/` |
| Черновик новой программы (тревога, выгорание и т.д.) | `materials/programs-draft/` |

Сомневаетесь — положите в ту, что ближе по смыслу, и напишите об этом в комментарии
к сохранению. Переложить несложно.

---

## Способ 2 — просто прислать файл

Если GitHub неудобен, присылайте текст как обычно — письмом или в мессенджере.
Кто-то из команды положит его в репозиторий. Минус: правки будут идти медленнее
и через посредника.

---

## Как называть файлы

Имя должно говорить, что внутри. Латиницей, без пробелов — дефис вместо пробела.

```
REAL-W1-A1.md            сценарий: программа REAL, неделя 1, практика A1
BOUND-W3-FINAL.md        программа BOUND, неделя 3, итоговая практика недели
standard-v1.0.md         стандарт
app-store-ru.md          описание для App Store
ANX-draft.md             черновик программы по тревоге
```

Для аудио-сценариев имя **обязано** совпадать с кодом практики — по нему файл
связывается с записью. Коды и темы всех 24 практик каждой программы уже заданы,
их пришлёт владелец проекта.

### Формат

Обычный текст с простой разметкой (Markdown):

```markdown
# Заголовок

Обычный абзац.

## Подзаголовок

- пункт списка
- ещё пункт

**Жирным** выделяется важное, *курсивом* — интонация.
```

Если привычнее Word — присылайте `.docx`, но тогда приложите и текстовую версию:
в Word не видно, что именно изменилось между правками, а это нужно.

## Три правила, которые важнее остальных

### 1. Запрещённые слова

Это не стилистика, а требование стандарта (§16). Нарушение придётся править
по всему продукту:

| Нельзя | Пишем |
|---|---|
| диагностика, диагноз, тест (как оценка состояния) | **самопроверка** |
| модуль | **маршрут** или **программа** |

Продукт прямо говорит пользователю: «мы не ставим диагнозов и не заменяем работу
с психологом». Любое слово из медицинского словаря это обещание нарушает.

### 2. Никаких персональных данных

Не присылайте примеры из реальных дневников, переписок, скриншоты с чужими
текстами. Это продукт о психологической поддержке — здесь утечка дороже всего
остального. Нужен пример — придумайте его.

### 3. Тон

Спокойный, на «вы», без давления и без обещаний быстрого результата.

Как звучит продукт сейчас:

> «Спокойные 6-недельные маршруты работы с собой — шаг за шагом, в вашем темпе.»

> «На сегодня всё — спокойно возвращайтесь завтра, один день за раз.»

Чего избегаем: «всего за 6 недель», «гарантированный результат», «измените свою
жизнь», восклицательных знаков, мотивационного напора.

## Что происходит после того, как вы прислали

1. Материал лежит в `materials/` — это **ещё не продукт**.
2. Разработчик переносит его в рабочий формат (`content/`).
3. После загрузки на сервер текст видят пользователи.

Между вашей правкой и тем, что видит человек в приложении, есть шаг переноса.
Если правка срочная — скажите об этом отдельно, сама по себе она в продукт
не попадёт.

## Структура программы — для автора новой программы

Программа жёстко структурирована, иначе её не загрузить. Требуется ровно:

- **6 недель**, в каждой **7 дней**;
- у каждого дня: фокус дня, задание, квиз, **ровно 3 вопроса для размышления**;
- **10 вопросов самопроверки** на неделю (с весами ответов — их увидит только
  разработчик, пользователю баллы не показываются);
- **5 утренних + 5 вечерних маркеров состояния** на всю программу;
- **24 аудио-практики**: 6 недель × 4 (по одной на дни 1–2, 3–4, 5–6 и на день 7);
- финальный продукт программы и рекомендация, что делать дальше.

Отклонение от этой структуры — не «почти подойдёт», а отказ загрузки с перечнем
несоответствий. Если материал в неё не укладывается, скажите сразу: возможно,
менять надо структуру, а не материал.
