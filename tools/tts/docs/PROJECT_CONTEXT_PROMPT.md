# Контекст проекта: озвучка курса Mental Club / REAL через ElevenLabs

Скопируйте весь этот файл как первое сообщение другому боту/сессии, чтобы
продолжить работу без повторного объяснения с нуля.

## Что это за проект

Курс медитаций «Найти себя и вернуть смысл» (Mental Club / REAL),
2 программы × 6 модулей. Нужно озвучить все тексты клонированным голосом
пользователя через ElevenLabs и собрать это в автоматизированный пайплайн
(не ручная вставка в Studio одного файла за раз).

Пользователь — не разработчик, объясняет задачи разговорным языком
(часто голосовым вводом с опечатками/проглоченными словами), работает на
Mac (M4, без GPU) и Windows (RTX 3070, 8GB VRAM, использовалась только
для тестирования локальной альтернативы, см. ниже). Финальное решение:
всё озвучивается через облачный ElevenLabs API, GPU не нужен.

## Статус на сейчас

Рабочий пайплайн есть и провалидирован на реальных прогонах (в т.ч. ловил
и чинил живую ошибку API). В репозитории, который прикладывается к этому
промту, лежит актуальная версия всех скриптов. **Используйте файлы из
репозитория как источник истины**, а не код ниже в этом промте (здесь —
только объяснение архитектуры и история решений, в коде репозитория —
более поздние доводки).

## Архитектура пайплайна

```
исходник (.docx или .txt)
   → разбор: текст + теги интонации + отметки пауз [пауза N сек]
   → нарезка на сегменты (по предложению/абзацу)
   → TTS-запрос в ElevenLabs на каждый сегмент отдельно (с кэшем по хэшу)
   → склейка сегментов через pydub + вставка ТОЧНОЙ тишины между ними
   → mp3 → (опционально) чистка шума → (опционально) фоновая музыка
```

Ключевое архитектурное решение: **точные паузы и устойчивость голоса
обеспечивает не сама модель ElevenLabs, а код вокруг неё**. Модель
`eleven_v3` не умеет надёжно воспроизводить `<break time="Ns">` в длинных
текстах и вообще не принимает поля `previous_text`/`next_text` (на v3 это
даёт `400 Bad Request` — это НЕ баг пайплайна, это ограничение API).
Поэтому: текст режется на маленькие сегменты, каждый озвучивается
отдельным запросом, а между ними программно (pydub) вставляется тишина
ровно нужной длины.

## Два формата исходных скриптов

Файл `tts_pipeline_v3.py` в репозитории различает их автоматически по
расширению:

- **Формат A (`.docx`, Неделя 2)**: заголовки `Аудио N. Название`, текст
  в блоке `SCRIPT_FOR_VOICE`, пауза — `[пауза N сек]` (строчными), тег
  интонации перед **каждой** фразой, например `[с теплом]`,
  `[спокойно, тепло, медленно]`.
- **Формат B (`.txt`, Неделя 1)**: заголовок `REAL / <Неделя> / Аудио N`,
  тело в `SCRIPT_FOR_VOICE`, пауза — `[Пауза N сек]` (с заглавной), один
  общий тег на всё аудио вида `[СТИЛЬ: спокойный, тёплый, медленный...]`.

Оба вида русских тегов переводятся в английские теги для `eleven_v3`
(модель понимает теги только на английском), словари перевода —
`TAG_MAP`/`WORD_MAP` (формат A) и `STYLE_MAP` (формат B) в
`tts_pipeline_v3.py`.

**Если встретится третий формат исходника** (например, Неделя 3+
окажется структурирована иначе) — не пытайтесь впихнуть его в
существующие регулярки. Напишите отдельную пару
`read_scripts_X()`/`segment_X_audio()` по аналогии с уже существующими
и подключите через `load_and_segment()` по новому условию (например, по
имени файла или по наличию маркера в тексте).

## Важные доводки, сделанные по ходу тестирования (все уже в коде репозитория)

1. **`stability = 0.75`** (не 0.5 и тем более не строка `"natural"` —
   это была живая ошибка, API 422: `voice_settings.stability` принимает
   только float). Строковые уровни Creative/Natural/Robust существуют
   ТОЛЬКО в UI ElevenLabs Studio и соответствуют float 0.0/0.5/1.0.
   0.75 выбрано эмпирически: при более низкой стабильности каждый
   отдельно синтезируемый сегмент получает заметно разный тембр/шум
   (ElevenLabs документирует "randomness between each generation"),
   из-за сегментной архитектуры это слышно сильнее, чем при генерации
   одним большим запросом.
2. **`PAUSE_SCALE = 0.3`, `MAX_GAP_MS = 2000`** — авторские
   `[Пауза N сек]` в сценарии рассчитывались на ручную вставку в
   Studio и на слух оказались в разы длиннее нужного почти после каждого
   предложения. Все паузы домножаются на 0.3 и ограничиваются 2 секундами
   сверху. Подбиралось на слух — если на новом материале это звучит не
   так, крутите коэффициент, а не переписывайте логику.
3. **Первый сегмент каждого аудио — без тега стиля.** Тег перед первой
   фразой аудио (когда ещё нет предыдущего аудио-контекста у модели)
   проявлялся как неестественный взлёт интонации вверх в начале. Решение
   — `text_with_tag(seg, is_first=True)` отдаёт на первом сегменте текст
   без `[tag] ` префикса.
4. **`eleven_v3` не принимает `previous_text`/`next_text` вообще**, даже
   `null` в теле запроса — 400. Это отличает его от `eleven_multilingual_v2`,
   где эти поля валидны и реально улучшают связность между сегментами.
   В коде это учтено условием `if MODEL_ID != "eleven_v3":`.

Если видите в будущем коде кого-то из этих четырёх пунктов отменённым —
скорее всего, это откат к старой ошибке, а не сознательное решение.
Переспросите пользователя, прежде чем убирать.

## Правила очистки текста (TEXT_FIXES)

У курса есть два требования к стилю, которые нужно соблюдать при любой
правке или добавлении нового текста:

- **Гендерно-нейтральный язык.** Прошедшее время мужского рода
  ("я потерял", "я устал", "я начал") и модальные "должен"/"обязан"
  переписываются в настоящее время или нейтральные обороты: "я теряю" /
  "мне тяжело" / "я начинаю" / "мне нужно".
- **Ударения через комбинирующий акут** (Unicode U+0301 после гласной)
  там, где слово иначе читается неправильно. Основной кейс — слово
  "нача́ло" (существительное, с ударением на "а́") в отличие от глагола
  "начать", который модель и так читает верно.

Конкретные пары "было → стало" для уже обработанных недель лежат в
словаре `TEXT_FIXES` в `tts_pipeline_v3.py` — это просто `.replace()` по
точному совпадению фразы, так что для новой недели добавляйте туда новые
пары, не трогая существующие (они безопасно не сработают на тексте, где
такой фразы нет).

## Постобработка (три отдельных скрипта, идут ПОСЛЕ основного синтеза)

1. `clean_audio.py <файл.mp3>` — прогоняет через `POST
   /v1/audio-isolation`, убирает шум/щелчки, сохраняет как `*_clean.mp3`.
2. `detect_clicks.py <файл.mp3>` — не ElevenLabs API, чисто локальный
   анализ амплитуды (numpy), ищет короткие всплески громкости на фоне
   соседних кадров — чтобы не прослушивать весь файл руками в поисках
   щелчков-артефактов TTS. Выводит список таймкодов-кандидатов.
3. `add_music.py <файл.mp3>` — генерирует фон через `POST /v1/music`
   под длительность готового трека, кэширует сырую музыку на диск
   (`*_music_raw.mp3`, чтобы повторный подбор громкости не тратил API
   повторно), накладывает тише под голос.

Рекомендованный порядок: синтез основным пайплайном → `clean_audio.py` →
`detect_clicks.py` (ручная проверка подозрительных мест) → `add_music.py`.

## Что НЕ делать

- **Не трогать и не читать `creads.txt`** в папке проекта пользователя —
  это файл с учётными данными (вероятно, ключ ElevenLabs API). Он
  исключён через `.gitignore`. Никогда не включайте его содержимое ни в
  какой вывод, коммит или сообщение.
- **Не пытаться вызывать ElevenLabs API напрямую из песочницы/агентской
  среды**, если ваша среда похожа на описанную здесь: сетевой доступ там
  обычно ограничен allowlist'ом доменов и не включает `api.elevenlabs.io`.
  Если это так и у вас — честно скажите пользователю, что код нужно
  запускать на его машине (через `setup_and_test.sh` + `python3
  tts_pipeline_v3.py`), а не пытайтесь обойти ограничение.
- **Не переключайте API на строковые уровни стабильности** ("natural" и
  т.п.) — это гарантированная ошибка 422, см. пункт 1 выше.
- **Не добавляйте `previous_text`/`next_text` безусловно** — сработает
  для `eleven_multilingual_v2`, но сломает `eleven_v3` (400).

## Локальная альтернатива (бэкап, НЕ используется в проде)

Был полностью настроен и провалидирован локальный TTS — **Qwen3-TTS**
(Apache 2.0, русский язык поддерживается, клонирование голоса по
короткому референсному аудио) через WSL2 + CUDA на Windows с RTX 3070
(8GB VRAM). Рабочая связка: `pip install qwen-tts`, демо-сервер
`qwen-tts-demo --no-flash-attn` (флаг нужен, если `flash-attn` не
собрался — типично на потребительских GPU без точной версии CUDA
toolkit). Клонирование — отдельные вкладки в Gradio UI: "Clone &
Generate" (референс-аудио 15-30 сек + ТОЧНЫЙ транскрипт того, что в нём
сказано — не целевой текст!) и "Save/Load Voice" (сохраняет `.pt`-файл
для переиспользования голоса без повторной загрузки референса).

Это осталось нетронутым резервным вариантом на случай, если качество или
цена ElevenLabs вдруг перестанут устраивать — сейчас (после прослушивания
тестовых прогонов) пользователь явно выбрал облачный ElevenLabs v3 как
основной путь, потому что он не требует GPU вообще (работает и с Mac) и
качество признано достаточным.

## Пожелание по стилю общения с пользователем

Пользователь часто формулирует задачи голосом/разговорно, со сбивчивыми
формулировками и прыжками мысли. Уточняйте задачу своими словами перед
тем как бросаться кодить, если видите двусмысленность — но не
переспрашивайте то, что уже решено здесь (формат файлов, настройки
TTS, архитектура). Готовые файлы отдавайте целиком и сразу пригодными к
запуску, а не фрагментами для ручной сборки.
