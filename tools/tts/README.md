# Mental Club / REAL — озвучка курса через ElevenLabs

Автоматическая озвучка медитативных скриптов курса «Найти себя и вернуть
смысл» (2 программы × 6 модулей) клонированным голосом через ElevenLabs
(`eleven_v3`), с точными паузами и интонационными тегами.

## Как это устроено

Один прогон = один аудио-файл:

```
исходник (.docx или .txt)
   │
   ▼
разбор скрипта: текст + теги интонации + отметки пауз [пауза N сек]
   │
   ▼
нарезка на короткие сегменты (по предложению/абзацу)
   │
   ▼
для каждого сегмента — отдельный запрос в ElevenLabs TTS (с кэшем по хэшу)
   │
   ▼
склейка через pydub: между сегментами вставляется ТОЧНАЯ тишина нужной
длины (не многоточия, не SSML — просто нарезанный и склеенный звук)
   │
   ▼
mp3 на выходе → (опционально) очистка шума → (опционально) фоновая музыка
```

Почему именно так: `eleven_v3` не умеет надёжно держать `<break time="Ns">`
и не принимает `previous_text`/`next_text` вообще (на v3 это даёт 400).
Поэтому точность пауз и связность обеспечивает не сама модель, а код —
разбивка на сегменты и ручная склейка тишиной средствами `pydub`.

## Форматы исходников

Пайплайн понимает оба формата автоматически (по расширению файла):

- **Формат A — `.docx`** (Неделя 2): `Аудио N. Название`, тело в блоке
  `SCRIPT_FOR_VOICE`, пауза — `[пауза N сек]` (со строчной буквы), тег
  интонации перед **каждой фразой**, например `[с теплом]`.
- **Формат B — `.txt`** (Неделя 1): заголовок `REAL / <Неделя> / Аудио N`,
  тело в `SCRIPT_FOR_VOICE`, пауза — `[Пауза N сек]` (с заглавной), **один**
  общий тег `[СТИЛЬ: ...]` на всё аудио.

Оба тега переводятся в английские теги ElevenLabs v3 (`[calm, warm, slow
pace]` и т.п.) — словари перевода лежат в `tts_pipeline_v3.py`
(`TAG_MAP`/`WORD_MAP`/`STYLE_MAP`).

## Файлы в репозитории

| Файл | Назначение |
|---|---|
| `tts_pipeline_v3.py` | основной пайплайн: разбор → синтез → склейка |
| `clean_audio.py` | прогон готового mp3 через ElevenLabs Audio Isolation (чистка шума/щелчков) |
| `add_music.py` | генерация и наложение фоновой музыки через ElevenLabs Music API |
| `detect_clicks.py` | эвристический поиск щелчков/артефактов в готовом mp3 — чтобы не слушать всё руками |
| `setup_and_test.sh` | разовая настройка окружения + пробный (без API) разбор файла |
| `requirements.txt` | python-зависимости |
| `.gitignore` | исключает секреты, venv, кэш, готовые mp3 |

Сами тексты курса (`.docx`/`.txt`) в репозиторий класть осмысленно —
это не секрет, но решайте сами: если курс ещё не публичный, тоже держите
приватным репозиторием.

## Установка

```bash
git clone <ваш-репозиторий>
cd <репозиторий>
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
brew install ffmpeg             # macOS; Linux/WSL: sudo apt install ffmpeg
```

На Python 3.13+ `pydub` требует отдельный пакет `audioop-lts` — он уже
в `requirements.txt` с условием версии, вручную ставить не нужно.

Пакетом `qwen-tts` локальная модель (GPU-альтернатива) в репозиторий не
входит — она не понадобилась после того, как качество `eleven_v3`
оказалось достаточным. Если понадобится вернуться к локальному варианту,
смотрите раздел «Локальный вариант» ниже.

## Настройка голоса и ключа

1. В ElevenLabs склонируйте голос (Instant Voice Clone хватает), скопируйте
   его **Voice ID** из дашборда.
2. Впишите его в `tts_pipeline_v3.py`:
   ```python
   VOICE_ID = "ваш_voice_id"
   ```
3. Экспортируйте ключ API (не коммитьте его никуда!):
   ```bash
   export ELEVENLABS_API_KEY="ваш_ключ"
   ```

## Запуск

```bash
# 1. Сухой прогон — проверить разбивку на сегменты, без обращения к API
python3 tts_pipeline_v3.py --dry-run --input "REAL_Week_1_4_audio_voice_scripts.txt"

# 2. Озвучить конкретное аудио из файла (нумерация — по порядку в файле)
python3 tts_pipeline_v3.py --input "REAL_Week_1_4_audio_voice_scripts.txt" --only 1

# 3. Тест на части текста (не тратить токены на весь файл)
python3 tts_pipeline_v3.py --input "REAL_Week_1_4_audio_voice_scripts.txt" --only 1 --limit 5

# 4. Перегенерировать один сегмент (например, если в середине проскочил артефакт)
python3 tts_pipeline_v3.py --input "..." --only 1 --redo 17

# 5. Озвучить всё в файле
python3 tts_pipeline_v3.py --input "REAL_Неделя_2_ОЧИЩЕНО.docx"
```

Или одной командой через обёртку (создаёт venv, ставит зависимости,
делает сухой прогон):

```bash
./setup_and_test.sh "REAL_Week_1_4_audio_voice_scripts.txt" --only 1
```

Результат — `output/audio_<название>.mp3`. Сегменты кэшируются в
`cache/` по хэшу (voice+model+settings+текст), так что повторный запуск
не тратит токены на уже готовые куски — это удобно при `--redo`.

### Постобработка (опционально)

```bash
export ELEVENLABS_API_KEY="..."

# убрать шум/щелчки
python3 clean_audio.py output/audio_Неделя_1_Аудио_1.mp3

# найти оставшиеся щелчки/артефакты, чтобы не слушать всё руками
python3 detect_clicks.py output/audio_Неделя_1_Аудио_1_clean.mp3

# наложить тихую фоновую музыку
python3 add_music.py output/audio_Неделя_1_Аудио_1_clean.mp3
```

## Важные настройки внутри `tts_pipeline_v3.py`

- `VOICE_SETTINGS["stability"] = 0.75` — поднято с 0.5: при низкой
  стабильности каждый сегмент синтезируется отдельным запросом, и
  "randomness between each generation" (см. доки ElevenLabs) даёт разный
  голос/шум почти на каждой фразе. 0.75 ближе к Robust — стабильнее голос
  между сегментами.
- `PAUSE_SCALE = 0.3`, `MAX_GAP_MS = 2000` — исходные `[Пауза N сек]`
  были рассчитаны на ручную вставку в Studio и на слух оказались в разы
  длиннее нужного. Паузы сжимаются этим коэффициентом (максимум 2 сек),
  чтобы медитация не растягивалась. Подбирается на слух — если на вашем
  материале долгие паузы ощущаются уместными, поднимите `PAUSE_SCALE`.
- Первый сегмент каждого аудио синтезируется **без** тега стиля
  (`text_with_tag(..., is_first=True)`) — тег перед первой фразой, когда
  ещё нет предыдущего аудио-контекста, провоцирует у v3 неестественный
  взлёт интонации вверх.
- `eleven_v3` не принимает поля `previous_text`/`next_text` вообще (даже
  `null`) — даёт 400. Пайплайн отправляет их только если `MODEL_ID !=
  "eleven_v3"` (для `eleven_multilingual_v2`, где они валидны и улучшают
  связность между сегментами).

## Частые ошибки

- **API 422, `stability` не парсится как число** — в код когда-то попало
  `"stability": "natural"` (строка). Строковые уровни Creative/Natural/
  Robust существуют только в UI Studio; в API это float 0.0/0.5/1.0
  соответственно. Сейчас уже исправлено на `0.75`.
- **`externally-managed-environment` при `pip install`** (macOS/новый
  Python) — нужен venv, см. раздел «Установка».
- **`ModuleNotFoundError: No module named 'audioop'`** — Python 3.13+
  убрал этот модуль из стандартной библиотеки; ставьте `audioop-lts`
  (уже в `requirements.txt`).
- **Модель в ElevenLabs Studio UI по умолчанию `Eleven Multilingual v2`**
  — она не понимает теги в квадратных скобках вообще (читает их как
  текст). Для ручных тестов в Studio переключайте модель на `Eleven v3`.
- **`ffprobe not found`** при загрузке аудио в любые Gradio-подобные
  интерфейсы — поставьте `ffmpeg` (он включает `ffprobe`).

## Безопасность

`creads.txt` и любой файл с ключом API/паролями **никогда** не должен
попасть в git — он в `.gitignore`. Если такой файл уже был закоммичен
в истории, его недостаточно удалить обычным коммитом — ключ нужно
перевыпустить в ElevenLabs и почистить историю git (`git filter-repo`
или аналог).

## Локальный вариант (бэкап, не используется в проде)

Был протестирован **Qwen3-TTS** (Apache 2.0, поддерживает русский,
клонирование голоса по короткому референсному аудио) через WSL2 + CUDA
на Windows (RTX 3070, 8GB VRAM) — рабочий, но после того, как качество
`eleven_v3` оказалось достаточным, от локального инференса отказались
в пользу облачного API (не требует GPU вообще, работает и с Mac).
Если понадобится вернуться:

- пакет `qwen-tts` (PyPI), демо через `qwen-tts-demo --no-flash-attn`
  (флаг `--no-flash-attn` нужен, если `flash-attn` не собрался — это
  нормально на потребительских GPU);
- клонирование голоса — вкладка "Save/Load Voice": на вкладке "Clone &
  Generate" указываете короткий (15–30 сек) референс и точный
  транскрипт того, что в нём сказано (не текст, который хотите
  синтезировать!), на вкладке "Save Voice" сохраняете `.pt`-файл,
  который потом грузите через "Load Voice" для любого нового текста без
  повторной загрузки референса.
